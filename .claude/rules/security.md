# セキュリティルール

## 秘密と個人情報

- トークン、パスワード、秘密鍵をソースコードへ直接記載しない。
- 秘密は環境変数や秘密管理基盤で受け渡す。
- 本番の個人情報をテストデータとして使わない。
- ログ、エラー、Issue、PR、スクリーンショットへの混入を確認する。
- .env.exampleには変数名と説明を記載し、秘密の実値を入れない。

## 入力と出力

- 外部入力を信頼境界で検証する。
- 型、長さ、範囲、許容値を確認する。
- SQLはパラメータ化する。
- 未検証の文字列をシェルコマンドへ連結しない。
- HTML出力、ファイル名、パス、アップロードを利用方式に応じて検証する。

## 認証と認可

- 認証と認可を区別する。
- リソースへの権限をサーバー側で確認する。
- UIの非表示やクライアント側チェックだけでアクセスを制限しない。
- CORSを認証・認可の代わりにしない。

## 通信とブラウザ

- Cookie、CSRF、CORS、リダイレクトを利用方式に合わせて設計する。
- 外部通信先と送信データを必要最小限にする。
- 再試行時の重複更新を考慮する。

## 依存と運用

- 依存追加の必要性と信頼先を確認する。
- lockfileを尊重し、無関係な依存更新を混ぜない。
- データ削除や移行では影響範囲と復旧方法を確認する。
- 内部例外や構成情報を公開レスポンスへ露出させない。

このファイルは行動指針であり、強制アクセス制御ではない。
権限と隔離は実行環境・CI・サービス設定でも制御する。
