# Code Review

## 目的

変更によって生じる具体的な問題を検出し、
修正判断に必要な根拠を提示する。

## 入力

対象Issue、PR、または比較範囲:

$ARGUMENTS

## 参照

- docs/standards/code-review.md
- docs/domain.md
- docs/architecture.md
- docs/work/README.md
- docs/work/<Issue番号>/analysis.md, plan.md, verification.md
- 対象Issue
- 変更差分と周辺コード
- テスト結果

パスはプロジェクトルートを基準とする。

## 手順

1. 比較元・比較先と作業ツリーの状態を特定する。
2. 受入条件と対象外を確認する。
   docs/work/<Issue番号>/ の分析、計画、検証結果があれば読み、
   計画との差と未検証範囲を把握する。
3. 差分に加え、呼び出し側、関連処理、テストを読む。
4. 問題になる入力や状態を追跡する。
5. 必要なローカル検証を行う。
6. 指摘をP0〜P3へ分類する。
7. 発生条件、影響、根拠、修正方向を示す。
8. 未検証範囲と残るリスクを記録する。

## 指摘の形式

- 重大度と短いタイトル
- ファイルと位置
- 発生条件
- 問題となる動作
- 影響
- 根拠
- 修正方向

事実と仮説を区別する。
同じ原因を重複して指摘しない。
好みの違いを不具合として扱わない。

## 出力

- 重大度順の指摘
- 確認した範囲
- 実行した検証
- 未検証事項

問題が見つからなければ明記する。
ただし、無欠陥を保証しない。

## 完了条件

- 指摘に具体的な条件と根拠がある
- 受入条件との対応を確認している
- レビュー範囲が明示されている

## 操作範囲

レビュー依頼だけで、コード変更、外部投稿、
マージを行わない。
