# Test Generation

## 目的

重要な振る舞いと不具合を検出できるテストを作成する。

## 入力

対象Issue、変更差分、または不具合:

$ARGUMENTS

## 参照

- docs/domain.md
- docs/architecture.md
- docs/stack.md
- docs/standards/testing-strategy.md
- 既存テストと実行設定

## 手順

1. 受入条件と不変条件を確認する。
2. 既存テストで確認できている範囲を調べる。
3. 正常、境界、異常、権限、外部障害から必要なケースを選ぶ。
4. 単体・結合・E2Eのどこで確認するか決める。
5. 期待結果を仕様から定義する。
6. 既存ツールを使用してテストを追加する。
7. 時刻、乱数、外部I/O、データ状態を制御する。
8. 不具合修正では可能なら修正前の失敗を確認する。
9. テストを実行し、失敗原因を切り分ける。
10. 結果と未検証事項を報告する。

## 避けること

- 実装と同じ計算をテスト側で再実装するだけ
- 内部関数の呼び出し順だけを確認する
- 不要なモックで重要な境界を隠す
- 成功させるために仕様を変える
- 理由のないskipや期待値変更
- 実行順序に依存するテスト

## 出力

- ケースと受入条件の対応
- 選択したテスト層と理由
- 追加・変更したテスト
- 実行コマンドと結果
- 検出した不具合
- 未実施項目と理由

## 完了条件

- 期待結果に仕様上の根拠がある
- 必要なケースが既存テストと合わせて確認できる
- 実行結果が記録されている

## 作業範囲

本体の修正が依頼範囲外なら、検出結果を報告する。
無関係な実装変更を行わない。
