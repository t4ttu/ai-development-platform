# Test Generation

## 目的

重要な振る舞いと不具合を検出できるテストを作成する。

## 入力

対象Issue、変更差分、または不具合:

$ARGUMENTS

## 参照

- docs/domain.md
- docs/architecture.md
- docs/standards/testing-strategy.md
- 既存テストと実行設定

パスはプロジェクトルートを基準とする。

## 手順

1. 受入条件と不変条件を確認する。
2. 既存テストで確認できている範囲を調べる。
3. 採用済みのテストツールと実行方法を確認する。
4. 正常、境界、異常、権限、外部障害から必要なケースを選ぶ。
5. 単体・結合・E2Eなどの検証方法を決める。
6. 期待結果を仕様から定義する。
7. テストを追加し、外部依存と状態を制御する。
8. 不具合修正では可能なら修正前の失敗を確認する。
9. 実行し、失敗原因を切り分ける。
10. 結果と未検証事項を報告する。

## テスト環境が未整備の場合

必要な検証、導入候補、導入範囲を整理する。
無関係なテスト基盤の入れ替えを行わない。

導入できない場合は、代替検証と未確認範囲を明示する。

## 避けること

- 実装と同じ計算を再実装するだけのテスト
- 内部呼び出し順だけを確認するテスト
- 過剰なモックで重要な境界を隠すこと
- 成功させるための仕様変更
- 理由のないskipや期待値変更
- 実行順序への依存

## 出力

- ケースと受入条件の対応
- 検証方法と選択理由
- 追加・変更したテスト
- 実行結果
- 検出した不具合
- 未実施項目と理由

## 完了条件

- 期待結果に仕様上の根拠がある
- 必要なケースを確認できる
- 実行結果と制約が記録されている

## 作業範囲

本体修正が依頼範囲外なら、検出結果を報告する。
無関係な実装変更を行わない。
