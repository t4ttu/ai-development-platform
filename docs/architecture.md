## 10. 検証方法

必須チェックの単一入口は `scripts/check.sh` とする。
hook、CI、手動実行はすべてこのスクリプトを経由する。

| 確認内容 | 手順・コマンド | 必須となる条件 |
|---|---|---|
| シェル・JSON・YAMLの構文 | `scripts/lint-syntax.sh` | 常に必須 |
| 文書の参照切れ | `scripts/lint-docs-references.sh` | 常に必須 |
| Ready確認欄と正本の整合性 | `scripts/lint-ready-checklist.sh` | 常に必須 |
| shellcheck | `scripts/lint-syntax.sh` 内で実行 | 参考扱い。未導入環境では未実施として報告する |
| テスト・型検査・ビルド | 未決 | 技術スタック決定後に定義する |

この基盤リポジトリは文書と設定が成果物であるため、
上の2件を必須チェックとしている。
技術スタックを決めたら、テスト、静的解析、型検査、ビルドを追加する。

手動確認が必要な項目は、この表に記載し、
自動検証されていないことを明示する。

### 10.1 必須チェックの設定手順

1. 上の表に、確認内容と実際のコマンドを記載する。
2. 同じ内容を `scripts/check.sh` の「必須チェックの定義」へ `run` 行として記述する。
3. 表とスクリプトの内容を一致させる。

手動確認のみの項目は、表に記載し `scripts/check.sh` には含めない。
その項目が自動検証されていないことを明示する。

### 10.2 終了コード

`scripts/check.sh` の終了コードは次のとおり。

| 終了コード | 意味 | 扱い |
|---|---|---|
| 0 | すべての必須チェックが成功 | 成功 |
| 1 | いずれかの必須チェックが失敗 | 失敗 |
| 2 | 必須チェックが未設定 | 成功ではない。未検証として扱う |

未設定のチェックを、必須チェックの実行済み項目として扱わない。
終了コード2を成功として報告しない。

### 10.3 実行される場所

| 場所 | 設定 | 動作 |
|---|---|---|
| ローカル（AIの作業時） | `.claude/settings.json` の Stop hook | 応答を返し終える直前に実行。失敗時は同一の失敗につき1回ブロックする |
| CI | `.github/workflows/ci.yml` | push と pull request で実行。終了コード1と2をいずれも失敗として扱う |
| 手動 | `scripts/check.sh` | 直接実行する |

hook はローカル環境に依存するため、CIと二重化する。
hook の設定だけをCIの成功として報告しない。
