# Issue分析: #10 存在しない参照先と不足している設定ファイルを修正する

- 対象Issue: #10
- 作成日: 2026-10-20
- 前提: #1（必須チェックの強制層）のマージ後（c3a0730）の状態で調査

## 要求の要約

開発者とAIが、文書に書かれた参照先とファイルを、記載どおりに辿れるようになる。

現在は文書が存在しないディレクトリやファイルを参照しており、
記載どおりに作業できない箇所がある。

## 受入条件

Issue本文に7項目が定義済み。観測可能な形式になっており、追加は不要。

ただし次の2点を更新する必要がある。

| 項目 | 状況 |
|---|---|
| `/doctor prompt-audit` で参照切れの指摘が出ない | **実行不可**。当該コマンドは v2.1.283 以降が必要で、現環境は v2.1.273。代替として #1 で導入した `scripts/lint-docs-references.sh` を使う |
| 全文書の相対パスが実在することを確認している | **#1 で自動化済み**。`scripts/lint-docs-references.sh` が必須チェックに入っており、手動確認は不要になった |

## 影響範囲

### 1. docs/adr/ が存在しない（根拠: 調査済み）

参照元が4箇所ある。

| ファイル | 内容 |
|---|---|
| `docs/standards/architecture-guidelines.md:132` | §11 でADRの記載項目を10項目定義 |
| `docs/architecture.md:155` | §13 から参照 |
| `docs/standards/development-workflow.md:488` | §8 記録の置き場所 |
| `docs/work/README.md:74` | §7 完了後の扱い（#2 で追加） |

記載項目が定義済みのため、テンプレートの内容は確定している。
新規作成のみで、既存文書の変更は不要。

### 2. .env.example が存在しない（根拠: 調査済み）

`.gitignore:4` に `!.env.example` の除外解除があるが、対象ファイルが無い。
現状では無害だが、除外解除の意図が成立していない。

### 3. 軽微な報告の経路が無い（根拠: 調査済み）

`config.yml` は `blank_issues_enabled: false` で、`contact_links` も無い。
テンプレートの必須項目数は次のとおり。

| テンプレート | 必須 / 全項目 |
|---|---|
| usecase.yml | 7 / 8 |
| bug.yml | 6 / 7 |
| task.yml | 5 / 7 |

Issue本文には「usecase.yml は7項目中6項目が必須」と記載があるが、
実際は8項目中7項目が必須である。本文の数値を訂正する。

### 4. 秘密管理の既定方針が無い（根拠: 調査済み）

`docs/architecture.md` §7 は「未決」のまま。
`.claude/rules/security.md` は「秘密はプロジェクトで定めた管理方法を使用する」と
するが、基盤側に既定が無いため各プロジェクトで再決定になる。

### 5. .claude/rules/local/ が存在しない（根拠: 調査済み）

参照元は `README.md:195` の1箇所のみ。
「置いてもよい」という任意の慣例の記述であり、不在そのものは誤りではない。
存在しないことが読み取れる書き方にするかの判断が必要。

### 自動検証への影響

`scripts/lint-docs-references.sh` の `allowed_missing` に
`docs/adr/` と `.claude/rules/local/` が登録されている。

本Issueの対応時に、この一覧から該当エントリを削除する必要がある。
削除漏れがあると、実在するようになった参照が
「例外リストから削除できます」と報告され続ける。

### 内部実装の判断（既存方針で判断可能）

- ADRテンプレートのファイル名（`0000-template.md` を想定）
- `.env.example` に書く変数名（現時点で必要な変数が無いため、書式例とコメントのみ）
- テンプレート自体がADRではないことの明示方法

## リスクと依存関係

- **#2 との依存**: `docs/work/README.md` が `docs/adr/` を参照している。本Issueの対応順は #2 の後が望ましい（既に #2 で参照が追加済み）
- **`usecase.yml` の編集競合**: #3（Ready チェックリストの追加）が同じファイルを編集する。必須項目の見直しを行う場合は #3 と順序を調整する
- **空ディレクトリ**: Git は空ディレクトリを管理できない。`docs/adr/` はテンプレートファイルを置くことで成立する
- **検証上の制約**: Issue テンプレートの表示確認は GitHub へ反映後にしか行えない。ローカルでは YAML 構文確認までが限界（`scripts/lint-syntax.sh` が実施）
