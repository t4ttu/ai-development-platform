# 実装計画: #18 READMEの§1と§9を2方式へ対応させる

- 対象Issue: #18
- 分析: Issue #18 本文に記載済み
- 作成日: 2026-10-23

## 目的と範囲

README §1 と §9 が履歴を共有する方式だけを前提にしていたため、
実際の運用と食い違っていた。両方式を文書化する。

対象外:

- どちらかの方式を廃止すること
- `PLATFORM_BASE` の更新を機械的に検査する仕組み
- 既存の派生プロジェクト（kakeibo）の変更

## 解消した未決事項

### どちらを既定として示すか

**方式A（履歴を共有しない）を既定**とした。

理由は、最初の派生プロジェクト（kakeibo）で実際にこの方式が選ばれたこと。
アプリの履歴にアプリ以外のコミットを入れない利点を優先する判断だった。

方式Bは「取り込みの管理を自動にしたい場合」「基盤を頻繁に改善し
その都度取り込む運用」として併記する。
どちらが優れているという書き方はしない。判断基準を示す。

## 実装方針

### §1 の構成

方式の選択を先に置き、方式ごとの手順を分け、初期化は共通化する。

| 節 | 内容 |
|---|---|
| 1.1 | 方式の選択（比較表と判断基準） |
| 1.2 | 方式A の手順。テンプレートから作る／cloneして履歴を作り直す。PLATFORM_BASE の形式 |
| 1.3 | 方式B の手順 |
| 1.4〜1.8 | 共通の初期化（作業記録、除外リスト、ラベル、必須チェック、内容記載） |

共通の初期化は #15 の検証で必要と分かった手順であり、方式に依存しない。

### §9 の構成

9.1（一覧）だけを方式で分け、9.2 以降は共通にする。
9.4 に方式Aの `PLATFORM_BASE` 更新手順を加える。

方式Bで2点比較を使わない理由（#9 で実測した内容）はそのまま残す。

### テンプレートリポジトリの扱い

基盤は `isTemplate=true` にしてある。
「Use this template」を押しても破綻しないよう、
方式Aの正規の入口として位置付ける。

冒頭の「このひな形について」にも、テンプレートとclone両方が
使えることを明記する。
