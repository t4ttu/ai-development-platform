# 実装計画: #9 派生プロジェクトへの改善反映を計算可能にする

- 対象Issue: #9
- 分析: Issue #9 本文に記載済み
- 作成日: 2026-10-23

## 目的と範囲

基盤側の改善点を、派生プロジェクトから機械的に差分として取得できるようにする。

README §9 は手動比較を求めていたが、派生プロジェクトに
どのバージョン由来かの記録が無く、手順1「基盤側の変更内容を確認する」と
手順2「コピー先の変更との差を比較する」が実行できなかった。

対象外:

- 自動更新の仕組み（無条件上書きをしない方針に反する）
- 既存の派生プロジェクトの遡及対応（派生プロジェクトは存在しない）

## 解消した未決事項

### 方式の選択

Issue本文の3案から、**clone して履歴を共有する方式**を採用した。

| 案 | 判定 | 理由 |
|---|---|---|
| バージョン記録（`PLATFORM_VERSION`） | 不採用 | SHAの手動更新が必要で、更新漏れで計算が狂う |
| Git リモート（template repo） | 不採用 | template repoは**共通の履歴を持たない**ため、結局マーカーファイルが必要になる |
| Git リモート（clone して履歴共有） | **採用** | 共通祖先があるため、未取り込みの差分をgitが計算できる。マーカー不要 |
| symlink（`.claude/rules/` のみ） | 不採用 | #5 と両立しない（下記） |

当初は template repo を想定していたが、
GitHubのtemplate repoから作ったリポジトリは基盤と共通の履歴を持たない。
そのため差分計算に別途マーカーファイルの手動管理が必要になることが分かり、
clone 方式へ変更した。

### `.git` 履歴の引き継ぎ

**引き継ぐ**。これが差分計算の前提になる。

派生プロジェクトの履歴の根元に基盤の開発履歴が残るが、
マーカーファイルの手動管理を避けられる利点を優先した。

### #5 との競合の解消

Issue本文で指摘した #5（`.claude/rules/` の `paths:` 化）との競合は、
symlink 方式を採らないことで解消した。

symlink 方式では、作業ディレクトリ外へのsymlinkが外部インポートの承認を必要とし、
承認後も `paths:` 付きルールはロードされない。
clone 方式はこの制約を受けないため、#5 は制約なく進められる。

## 調査で判明したこと

### 単純な2点比較では取り込み済みを判定できない

cherry-pick は新しいSHAのコミットを作るため、
取り込み後も `git log HEAD..platform/main` に元のコミットが出続ける。

実測で確認した。

| コマンド | 取り込み後の出力 |
|---|---|
| `git log --oneline HEAD..platform/main` | 出続ける（**誤り**） |
| `git log --oneline --cherry-pick --right-only HEAD...platform/main` | 空（正しい） |
| `git cherry -v HEAD platform/main` | `-` 印で取り込み済みと分かる |

`--cherry-pick` はパッチ等価なコミットを除外する。
README にはこちらを記載し、2点比較を使わない理由も明記する。

## 実装方針

README §1 と §9 を、実行可能なコマンド付きの手順へ書き換える。

### §1 利用開始

clone して platform リモートを残す方式に変更する。
あわせて、#15 の検証で必要と分かった手順を追加する。

- 基盤の作業記録（`docs/work/<基盤のIssue番号>/`）を外す
- `allowed_missing` を初期化する
- `usecase` / `task` ラベルを作る（無いとテンプレートからのIssue作成が失敗する）
- `./scripts/check.sh` の成功を確認する

これらは #15 の検証で手動実施したが、手順書に無かった。

### §9 改善反映

`--cherry-pick --right-only` による一覧、内容確認、cherry-pick、
取り込み後の確認、基盤への還元の5段に分ける。

platform リモートは参照専用とし、派生から基盤へ直接pushしない。

## 受入条件と検証

| 受入条件 | 検証方法 |
|---|---|
| 派生側で基盤のどのバージョン由来か特定できる | clone した履歴で確認 |
| 未取り込みの基盤変更を一覧でき、実際に実行して確認している | ローカルで派生を作って実行 |

| 無条件上書きをしない方針が維持されている | 文書の確認 |
